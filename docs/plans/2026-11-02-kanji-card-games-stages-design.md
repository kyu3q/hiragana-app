# 漢字カードゲーム ステージ制 設計

## 目的

漢字ランナーには、ステージ制を入れた。ほかの漢字カードゲームも、1回の勝利条件までを一本道で遊ぶだけで、進むにつれて変わるものがない。
ヘビ・ブロック・飛行機・バトルの4つに、3ステージずつのステージ制を入れる。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 対象 | ヘビ、ブロック、飛行機、バトルの4つ |
| 対象外 | キャッチ（`CatchGame.jsx`）、漢字ランナー（今回は触らない） |
| ステージ数 | 1ゲームにつき3ステージ |
| 世界観 | ゲームごとに違うテーマ（背景・絵文字・ステージ名） |
| 変えるもの | 難しさ（速さ・数・割合など）と見た目 |
| 変えないもの | 操作、BGM、`KanjiGameContainer` |
| 進み方 | クリアすると、つづけて次のステージへ進む |
| 保存 | しない。次に開くとステージ1から始まる |
| 画像ファイル | 追加しない。絵文字と canvas 描画で作る |

## 1. 共通の仕組み

共通部品を作り、4つのゲームから使う。

- `useStageFlow`：現在のステージ番号、ステージ間のスコアの引き継ぎ、ゲームオーバー時のやり直しを管理する。ロジックは純粋関数に分け、単体テストで確認する。
- `StageIntro`：「ステージ1　〇〇」を数秒出す表示。
- `StageClear`：「ステージクリア！」の画面と「つぎへ」ボタン。

各ゲームは、自分の設定データ（`xxxStages.js`）だけを持つ。設定を読み、そのステージの勝利条件に達したら `useStageFlow` に伝える。最終ステージのクリアだけ、今までと同じ `onComplete(true)` を呼ぶ。`KanjiGameContainer` は変更しない。

## 2. ゲームごとのステージ

| ゲーム | 今の勝利条件 | ステージ1 | ステージ2 | ステージ3 | 変えるもの |
|---|---|---|---|---|---|
| ヘビ | 500点 | はらっぱ | どうくつ | ようがん | 速さ、おじゃま漢字の割合、障害物、目標点 |
| ブロック | ブロックを全部壊す | おもちゃばこ | こおりのしろ | うちゅう | ボールの速さ、ブロックの配置と数、ライフ |
| 飛行機 | 距離3000 | あおぞら | くものうえ | よぞら | 飛ぶ速さ、障害物の密度、コースの長さ |
| バトル | 敵のHPを0にする | もりのスライム | やみのおおかみ | ドラゴンのしろ | 敵のHP、似た漢字の紛らわしさ、制限時間 |

見た目は、背景色、敵やアイテムの絵文字、ステージ名を変える。

## 3. 画面の流れ

- ステージが始まる直前に、名前を数秒出す。操作できるのは、そのあと。
- ステージ中は、画面の上に、いまのステージ番号（1/3）を小さく出す。
- クリア
  - ステージ1〜2：「ステージクリア！」の画面を出し、「つぎへ」で次のステージに進む。
  - ステージ3：`onComplete(true)` を呼ぶ。
- 画面に出すスコアは、ステージをまたいで引き継ぐ。`onAddScore` は、今の形のまま変えない。
- ゲームオーバーは、いまのステージの最初からやり直す。スコアは、そのステージの開始時点に戻す。
- ライフとHPは、ステージごとに最初の値に戻す。
- ヘビのように合計点で勝つゲームは、ステージごとに目標点を決め、ステージ開始時点からの増分で判定する。

## 4. 実装の分け方

1. 共通部品（`useStageFlow`、`StageIntro`、`StageClear`）とそのテスト
2. 4つのゲームの `xxxStages.js`（設定データ）とそのテスト
3. ゲームごとに書き換える。ステージの開始・クリア・やり直しの流れをつなぐ
4. 見た目をステージ設定で切り替える

ゲームごとにコミットを分ける。問題が出たとき、戻す範囲を小さくするため。

## 確認の方針

- `useStageFlow`：次のステージへ進む、最終ステージで完了する、ゲームオーバーでスコアを開始時点に戻す、を単体テストで確認する。
- 設定データ：難しさが段階的に上がること、値が妥当な範囲にあることを、単体テストで確認する。
- 見た目と操作は、ブラウザで3ステージを通して確認する。
- 既存のテストを壊さない。

## 確認できていないこと・リスク

- 4つとも `useEffect` の中の canvas ループで動き、状態を `ref` で持つ。ステージの切り替えで、ループの初期化と後片付けが二重にならないか、ゲームごとに確認が必要。
- バトルは、ゲームオーバーの処理が未実装の箇所がある（`BattleGame.jsx` 96行目付近）。やり直しの流れを入れるときに、あわせて整理する。
- 難しさの数値は、遊びながら調整する前提の初期値。
- 漢字ランナーを共通部品に載せ替えるかは、今回は決めない。

# 漢字ランナー ステージ制 設計

## 目的

漢字ランナー（`JumpGame.jsx`）は、毎回同じ見た目で、最初から最後まで同じ速さで進む。
4つのステージ（草原・砂漠・雪山・火山）に分け、進むにつれて見た目と難しさが変わるようにする。

## 決めたこと

| 項目 | 決定 |
|---|---|
| ステージの形 | 見た目と仕掛けが変わる（草原→砂漠→雪山→火山の4つ） |
| 変えるもの | 見た目（背景・色）、敵とトラップ（出る割合・見た目） |
| 変えないもの | BGM（今の1曲のまま）、物理、操作、チェックポイント |
| 進み方 | クリアすると、つづけて次のステージへ進む |
| 保存 | しない（Stage 3 のバックエンド保存の対象。今回は対象外） |
| 新しい種類の敵・トラップ | 作らない。見た目と出る割合の違いで段階づけする |

## 1. ステージの定義

ステージの違いは、1つの設定オブジェクトにまとめる。ゲームの中身は全ステージ共通で、設定の値だけを差し替える。

| | 草原 | 砂漠 | 雪山 | 火山 |
|---|---|---|---|---|
| 空・山・地面の色 | 今のまま | 黄土色の空と砂 | 白と水色、雪の粒 | 暗い赤、溶岩、火の粉 |
| 走る速さ（今 = 1.0） | 1.0 | 1.1 | 1.2 | 1.3 |
| コースの長さ | 7000 | 8000 | 9000 | 10000 |
| スライム:鳥:トゲの割合 | 今のまま | トゲ多め | 鳥多め | 全部多め |
| 敵の見た目 | スライム・鳥・トゲ | サソリ・ハゲタカ・サボテン | 雪だるま・ペンギン・氷柱 | 火のスライム・コウモリ・溶岩のトゲ |

- 敵の当たり判定と動きは、今の3種類（slime / bird / spike）のまま。見た目と割合だけを変える。
- 設定は `stages.js` に純粋なデータとして置く。速さ・長さ・割合は、テストで確認できる。
- 漢字、BGM、チェックポイントの仕組みは、全ステージで今のものを使う。

## 2. 画面の流れ

- ステージが始まる直前に、「ステージ1　そうげん」のように名前を数秒出す。操作できるのは、そのあと。
- ステージ中は、画面の上に、いまのステージ番号（1/4）を小さく出す。
- クリア
  - ステージ1〜3：「ステージクリア！」の画面を出し、「つぎへ」で次のステージに進む。
  - ステージ4：今までと同じ形で `onComplete(true)` を呼ぶ。コンテナ側は変更しない。
- 画面に出すスコアは、ステージをまたいで引き継ぐ。`onAddScore` は、アイテムを取るたびに呼ぶ今の形のまま変えない。
- ゲームオーバーは、いまのステージの最初からリトライする。スコアは、そのステージの開始時点に戻す。
- 途中でやめたら、進み具合は保存しない。次に開くとステージ1から始まる。
- ライフは、ステージごとに最初の数に戻す。

## 3. 実装の分け方

1. `stages.js`：4ステージの設定データと、そのテスト
2. `JumpGame.jsx`：設定を読んで、コース生成・色・敵の見た目・速さを切り替える
3. ステージの流れ：名前表示、クリア画面、合計スコア

## 確認の方針

- 設定データ（4ステージ分、速さ・長さが段階的に上がること、割合の合計）は、単体テストで確認する。
- 見た目と流れは、ブラウザで4ステージを通して確認する（一時的な確認用ファイルで、ステージを直接指定して測る）。
- 既存のテスト（137件）を壊さない。

## 確認できていないこと・リスク

- 速さ（1.0〜1.3）とコースの長さは、遊びながら調整する前提の初期値。
- 速さを上げると、ジャンプの距離と足場・敵の間隔の関係が変わる。間隔は速さに合わせて広げる必要があるか、実装時に測る。
- 敵の見た目は絵文字か canvas の描画で作る。画像ファイルは追加しない予定。

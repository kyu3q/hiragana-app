# メール認証システム設計書

## 概要

ひらがなアプリのログイン方式を改善し、実在するメールアドレスの確認機能とパスワードリセット機能を実装する。

## 目的

- 適当なメールアドレスでの登録を防止
- パスワードを忘れた際のリセット機能を提供
- セキュリティの向上

## 技術スタック

- **バックエンド:** Java Spring Boot
- **メール送信:** Gmail SMTP (JavaMailSender)
- **認証:** 既存のJWT認証を継続使用
- **フロントエンド:** React

## 実装する機能

### 1. メールアドレスのバリデーション
- 登録時に形式チェック（正規表現）
- 重複チェック（既存機能）

### 2. メール確認機能
- ユーザー登録時に確認用トークンを生成
- 確認メールを送信
- トークンを検証してアカウントを有効化
- 未確認ユーザーはログイン不可

### 3. パスワードリセット機能
- メールアドレスでリセット依頼
- リセット用トークンを生成・送信
- トークン検証後、新パスワードを設定

## アーキテクチャ設計

### データベース変更

**usersテーブルに追加するカラム:**

| カラム名 | 型 | 説明 |
|---------|-----|------|
| email_verified | BOOLEAN | メール確認済みフラグ（デフォルト: false） |
| verification_token | VARCHAR(255) | メール確認用トークン（UUID） |
| token_expiry | DATETIME | 確認トークンの有効期限 |
| reset_token | VARCHAR(255) | パスワードリセット用トークン（UUID） |
| reset_token_expiry | DATETIME | リセットトークンの有効期限 |

### 新規サービスクラス

#### EmailService
**責務:** メール送信を担当

**主要メソッド:**
- `sendVerificationEmail(String to, String token)` - 確認メール送信
- `sendPasswordResetEmail(String to, String token)` - リセットメール送信

**設定 (application.properties):**
```properties
spring.mail.host=smtp.gmail.com
spring.mail.port=587
spring.mail.username=${GMAIL_USERNAME}
spring.mail.password=${GMAIL_APP_PASSWORD}
spring.mail.properties.mail.smtp.auth=true
spring.mail.properties.mail.smtp.starttls.enable=true

# フロントエンドURL（確認リンク生成用）
app.frontend.url=${FRONTEND_URL}
```

**注意:** Gmailアプリパスワード（App Password）が必要。2段階認証を有効化して生成。

### 既存サービスの変更

#### UserService
**追加機能:**
- `generateVerificationToken()` - 確認トークン生成（UUID、有効期限24時間）
- `verifyEmail(String token)` - トークン検証・アカウント有効化
- `generateResetToken(String email)` - リセットトークン生成（UUID、有効期限1時間）
- `resetPassword(String token, String newPassword)` - パスワード更新

#### AuthController
**追加エンドポイント:**

```
POST /api/auth/verify-email?token={token}
  説明: メール確認処理
  処理: トークン検証、有効期限チェック、email_verified=true に更新
  レスポンス: 成功/失敗メッセージ

POST /api/auth/forgot-password
  Body: { "email": "..." }
  説明: パスワードリセット依頼
  処理: リセットトークン生成・保存、リセットメール送信
  レスポンス: 常に成功メッセージ（セキュリティ対策）

POST /api/auth/reset-password
  Body: { "token": "...", "newPassword": "..." }
  説明: パスワード更新
  処理: トークン検証、パスワード更新
  レスポンス: 成功/失敗メッセージ

POST /api/auth/resend-verification
  Body: { "email": "..." }
  説明: 確認メール再送信
  処理: 新しいトークン生成、確認メール再送信
  レスポンス: 成功メッセージ
```

**既存エンドポイントの変更:**

```
POST /api/auth/login
  追加チェック: email_verified が false の場合はエラー
  エラーメッセージ: "メールアドレスが未確認です。確認メールをご確認ください。"
```

## ユーザーフロー

### メール確認フロー

1. ユーザーが登録フォームに入力（メール、ニックネーム、パスワード）
2. サーバーが受信、バリデーション
3. ユーザーレコードを作成（`email_verified=false`）
4. 確認トークン生成（UUID、有効期限24時間）
5. 確認メール送信: `${frontendUrl}/verify?token=${token}`
6. 「確認メールを送信しました」画面を表示
7. ユーザーがメール内のリンクをクリック
8. フロントエンドが `/verify?token=...` に遷移
9. バックエンドに確認リクエスト送信
10. トークン検証成功 → `email_verified=true` に更新
11. 「メール確認完了。ログインできます」画面を表示
12. ログイン可能に

### パスワードリセットフロー

1. ログイン画面で「パスワードを忘れた」クリック
2. メールアドレス入力画面
3. メールアドレス送信
4. サーバーがリセットトークン生成（UUID、有効期限1時間）
5. リセットメール送信: `${frontendUrl}/reset-password?token=${token}`
6. 「リセットメールを送信しました」メッセージ表示
7. ユーザーがメール内のリンクをクリック
8. 新しいパスワード入力画面
9. 新パスワード送信
10. トークン検証、パスワード更新
11. 「パスワードを変更しました」画面を表示
12. ログイン画面へ遷移

## フロントエンド変更

### 新規ページ

**1. `/verify` - メール確認ページ**
- URLパラメータからトークンを取得
- 自動的にバックエンドにリクエスト
- 成功/失敗メッセージを表示
- ログインボタン表示

**2. `/forgot-password` - パスワードリセット依頼ページ**
- メールアドレス入力フォーム
- 送信ボタン
- 「メールを送信しました」メッセージ

**3. `/reset-password` - 新パスワード入力ページ**
- URLパラメータからトークンを取得
- 新パスワード入力フォーム（確認用も）
- 送信ボタン
- 成功後、ログイン画面へ遷移

### 既存ページ修正

**ログイン画面:**
- 「パスワードを忘れた」リンク追加 → `/forgot-password` へ

**登録画面:**
- 登録成功後、「確認メールを送信しました。メールをご確認ください。」メッセージ
- 「確認メールが届かない場合」再送信リンク

## セキュリティ設計

### トークンの安全性

- **トークン形式:** UUID（128ビット、推測不可能）
- **有効期限:**
  - 確認メール: 24時間
  - パスワードリセット: 1時間
- **使用後の処理:** トークンをnullにして再利用を防止
- **上書き:** 同じメールで複数回リクエストした場合、前のトークンを無効化

### メールアドレスの列挙攻撃対策

パスワードリセット時、存在しないメールアドレスでも成功メッセージを返す。
「メールアドレスが存在する場合、リセットメールを送信しました。」

### レート制限（推奨）

- メール送信: 同一IPから1時間に5回まで
- ログイン失敗: 5回まで、その後アカウントロック（15分間）

### HTTPS必須

本番環境では必ずHTTPSを使用（トークンの漏洩防止）

## エラーハンドリング

### 想定エラーケースと対応

| エラーケース | 対応 |
|------------|------|
| トークンが無効・期限切れ | エラーメッセージ + 再送信リンク表示 |
| メール送信失敗 | ユーザーに通知、管理者ログに記録 |
| すでに確認済み | "すでに確認済みです。ログインしてください。" |
| 存在しないユーザー | セキュリティ上、成功メッセージを返す |
| パスワード形式エラー | "パスワードは8文字以上で設定してください" |
| ネットワークエラー | "サーバーに接続できません。もう一度お試しください。" |

### ユーザー体験の重視

- すべてのエラーメッセージは日本語
- 明確な次のアクション（再送信、ログイン等）を提示
- ローディング状態を適切に表示

## メール文面サンプル

### 確認メール

```
件名: 【ひらがなアプリ】メールアドレスの確認

こんにちは、

ひらがなアプリにご登録いただきありがとうございます。

以下のリンクをクリックして、メールアドレスを確認してください。
このリンクは24時間有効です。

[メールアドレスを確認する]
${frontendUrl}/verify?token=${token}

もしこのメールに心当たりがない場合は、このメールを無視してください。

ひらがなアプリチーム
```

```
以下のリンクをクリックして、新しいパスワードを設定してください。
このリンクは1時間有効です。

[パスワードをリセットする]
${frontendUrl}/reset-password?token=${token}

もしこのリクエストに心当たりがない場合は、このメールを無視してください。

ひらがなアプリチーム
```

## まとめ

この設計により、ひらがなアプリに標準的なメール認証とパスワードリセット機能が実装されます。

**主な利点:**
- セキュリティの向上
- 実在するメールアドレスのみ登録可能
- パスワードを忘れた際の自己解決が可能
- 業界標準のフローに準拠

**実装期間の目安:**
5つのステージを順番に実装。各ステージでテストを実施し、確実に動作することを確認してから次へ進む。
